GFW8 License Grabber - GUI v1.10.1
By Alec Breen | TheBreenis
https://github.com/thebreenis

Run the single versioned GFW8 License Grabber v<version>.exe. It carries the bundled backend; on first launch it unpacks and verifies a private versioned runtime. Windows 10/11
x64, Windows PowerShell 5.1 and Windows Microsoft-account SSO are required.
No Python, developer SDK or game installation is required. The backend's
temporary Appx registration must be allowed by Windows. This app does not
change that setting. Installed games support receipt acquisition only.

Choose a game from the 108-entry dropdown. With it focused, type multiple
letters to jump to a matching name; there is no editable search field.
For games not installed, Get pop.bin uses the account returned with the Windows receipt credential.
The header displays that email when Windows provides it. Xbox gamertag is
resolved from a successful token/profile lookup; until then it is explicitly
unavailable, never guessed from your email or the Xbox app's visible login.

Load existing receipt opens a file picker. It parses XML with DTD/external
entities disabled, verifies the whole-document signature against the pinned
Microsoft public certificate, checks Full edition and ReceiptDate+24 hours,
and then automatically selects the matching game. At 24 hours the receipt is
invalid and is not loaded. The source is never modified. No new certificate
chain/revocation validation is claimed. App-minted receipts skip the extra
signature-verification step as requested; edition/date are still checked.
Saved validation records and SHA256 detect changes before token acquisition.

Get Xbox token is optional. It uses the existing independent temporary helper,
with silent sign-in first and one PromptIfNeeded recovery if Windows requires
verification. Windows owns any credential dialog. The original attempt and
receipt are retained. Forced credential input is not automated.
Seven helper routes are verified locally; all 108 catalogue entries have token
attempt configurations. Other routes remain experimental. DML uses a tested
Windows 10 package identity with its legacy title ID. Modern Combat 5 uses its
supplied 5.8.7.0 Windows 10 identity and SPA-confirmed legacy title ID; live token
testing was blocked by no license. Dungeon Hunter 5 uses current Windows 10
identity metadata and user-accepted candidate title ID 1195776868; receipt and
token success are assumed for an entitled account, not independently proven.
PromptIfNeeded recovery now activates the helper window for Windows sign-in.
Token acquisition and Presence testing are available only for uninstalled games.

Receipt expiry is ReceiptDate+24 hours under the requested policy. Token expiry
comes from Xbox's actual response; Issued is its expiry-minus 4 hours reference,
since Xbox may backdate Created. A still-valid receipt can be reused to request
another token after token expiry, subject to service authorization.

After successful token acquisition, Copy to Clipboard appears. It copies the
complete native issued-token.xml, which is also saved to a private file.
No raw bearer values are shown in Activity. Changing games clears the active
receipt/token UI association but does not remove any saved files.

Test Xbox Presence is optional and changes Xbox activity. It reads the token's
profile, posts Presence, polls independent readback, and separately submits
legacy Last Played history. Results/HTTP errors are shown separately. This
does not establish achievement authorization or guarantee Xbox-profile UI
propagation. Existing active presence is preserved. Temporary test presence is
removed and absence polled when initially inactive. Cleanup uncertainty is
reported. No achievement endpoints are called.

Get every entitled pop.bin sequentially checks all 108 receipt entries. It
creates game folders only after a valid receipt is downloaded. Unlicensed and
failed checks stay in the batch summary log. The dropdown scrolls at half speed;
Tab commits the highlighted game and advances focus. Bulk counts errors and
never acquires tokens. Cancel stops between requests, preserving completed
files. A current HTTP request can take up to 45 seconds to finish. Receipt
entitlement coverage is not a guarantee every edition can issue a receipt.

Each action replaces its button with a progress display spanning all stages without resetting. Time estimates are
approximate duration, never a prediction of success. Windows verification pauses overall progress; long requests show Taking longer than usual instead of 0 seconds.

Activity is readable, scrollable, and has independent Copy to Clipboard and
Save Log actions. The displayed/exported log excludes bearer values, receipt
XML and account email. Account identity travels privately to the header.
Each distinct error is shown once per operation; a separate retry can report it
again. Successful background installation checks do not add Activity messages.

Open saved files opens:
  %LOCALAPPDATA%\GFW8LicenseGrabber
Per-run receipts, token exports, results and preservation backups are restricted
to your Windows account and SYSTEM. Treat issued-token.xml/native-token.txt
like temporary passwords. No receipts/tokens/saves/private logs are bundled.
Backend diagnostic files can contain private paths/data; share only sanitized
Activity logs. Save Log exports the current displayed Activity text.

The GUI runs operations in hidden background workers and stays responsive.
Closing while work is active waits for the current operation and helper cleanup;
bulk work is cancelled between requests. Complete/cancel a Windows sign-in
dialog to let authentication finish. Do not force-kill workers during cleanup.

The CLI backend is derived from the working v0.4 build. Its existing save/pop
preservation guards, pinned runtime hashes, original package versions and
temporary-registration cleanup remain enabled.

New output layout:
  Games\<package_family_name>\Receipts\<UTC run>\pop.bin
  Games\<package_family_name>\Tokens\<UTC run>\...
  Games\<package_family_name>\Presence\<UTC run>\...
  Batches\<UTC batch>\bulk-summary-private.json
  Logs\Jobs\<UTC operation>\...
  Runtime\<version-hash>\... (embedded backend cache)
Existing saved files are retained in their original folders.
The approved purple Windows 8 style icon is embedded in the EXE and used by the app window.

Installed games (v1.4):
Get pop.bin requests a fresh receipt directly from the Store service, whether or
not the game is installed. No game launch, cached-receipt refresh, installer,
package swap or additional confirmation is needed. Normal entitlement checks apply.

Token acquisition and Presence testing are disabled while the selected game is
installed. The background worker also checks installation before authentication
or Presence, so a stale UI selection cannot enable the removed flow. Loading a
receipt still selects its game and observes the same installed-game restriction.
For uninstalled games the existing token/PromptIfNeeded/expiry/copy/Presence steps
remain available. Bulk remains receipts only and performs no package changes.

Compatibility recovery only:
If an earlier v1.3 operation was interrupted after a package change, startup still
attempts its recorded restoration before new work. A failed restoration shows
Retry restoration / Close app and keeps recovery files. No new transactions can
be created. Do not delete retained PackageRecovery material while recovery remains
unfinished. The ordinary receipt/token flow has no package-swap or installer UI.

Window layout (v1.4.2):
The default window is 60 pixels shorter. The complete interface scales uniformly
when resized or maximized, including the game dropdown. Installed-game token
text explains the installation conflict and asks the user to uninstall and retry.

Local token-helper diagnostics (v1.4.3):
Complete child stdout/stderr is saved to driver-metadata.log. When available,
local-error-private.log records the underlying exception beside token-result.json.
These files are private; share only relevant exception text.

Receipt sharing (GUI 1.9.0 / CLI 1.5.0):
Open Receipt sharing at the bottom of the GUI, or press S in the CLI menu.
Create a temporary or permanent code and give it privately to your friend.
Your friend joins using that code. Pairing lets both people browse and pull the
selected shared games without further approval. Codes expire in 10 minutes.
Temporary pairs end on disconnect or after 2 hours. Permanent pairs reconnect
when the apps next open.

Select a paired computer and game, then Get selected pop.bin. The provider must
be online; the receipt is signature/date/edition checked before being saved.
Close the sharing window to apply the received receipt to the main GUI.
Imported receipts are not advertised as owned games, and Store ownership does
not change. Xbox tokens are requested locally by the recipient.

Background sharing is optional and off initially. Enable Keep sharing in
background to run a per-user tray agent after closing the app and at Windows
sign-in. The computer must remain awake, online and signed into Windows.
Pause sharing withdraws your list and blocks pulls. Choose which games to share,
or Unpair to revoke a relationship. Complete Windows sign-in yourself if needed.
No Cloudflare account or router port forwarding is needed on your friend's PC.

Receipt encoding (GUI1.9.0 / CLI1.5.0):
New receipt downloads and imports omit a leading UTF-8 BOM. Signed XML bytes
after the encoding marker are preserved. This fixes Adera treating the BOM as
literal characters and receiving Xbox SOAP error0x8015DB00. Existing signed
receipts are not bulk rewritten; importing one creates a normalized saved copy.

Sharing screen (GUI1.9.0 / CLI1.5.0):
Separate generated and join code fields, Metro window controls and main app icon.
Self-pairing is rejected locally; joining times out after30seconds and can be
cancelled. Up to4 concurrent transfers; Microsoft acquisitions stay sequential.
Scan My Licenses discovers owned licenses directly in Sharing. Full scans are
manual, cancellable, show freshness, and use a15minute precautionary cooldown.
Repeated scans may be throttled; HTTP429/Retry-After stops checks and backs off.
CLI sharing: S or --sharing; C starts a scan and V cancels it.

Install Receipts (GUI1.9.0 / CLI1.5.0):
Built into the main app; no separate executable. Choose a folder, ZIP, or 7z and Scan Receipts. Every subfolder is searched. Review the destinations, choose whether to include games that are not installed, then choose Install Receipts. The installer verifies signatures and signed dates, strips any UTF8 BOM, and chooses the newest valid receipt per game. Existing pop.bin files are replaced without backups. Running games, invalid/expired receipts, links, drive roots and Windows folders are skipped or rejected. Sources are not changed; unrelated game data is not modified. No Microsoft requests. CLI: press I in the main menu.

Sharing (GUI1.9.0 / CLI1.5.0):
Friend lists load once per connection and retain checked selections during status updates. Use Refresh Friend's List to load additions. Check individual games or Select All, then Download Checked. Cancel finishes the current download before stopping; the first failure stops the batch and completed receipts remain saved. Transfer Activity at the bottom right shows connected/disconnected peers, downloads, sends and receiver-confirmed saved downloads. Both peers should update for delivery confirmations. The latest200 events are kept privately across agent restarts. CLI Sharing: G accepts IDs or ALL; R refreshes lists; L shows activity.

Full and Trial receipts
-----------------------
The app keeps both Microsoft-signed Full and Trial pop.bin receipts. The activity
log and receipt card show the signed license type. Trial receipts may be used
for token requests; Xbox decides whether a token can be issued for each title.
Signatures, edition identity and the existing 24-hour receipt policy still apply.
Receipt XML is never changed to convert Trial to Full.

Receipt folders use the local issue time and license type, for example:
  Receipts\2026-11-13 20-54-18 - Trial\pop.bin
  Receipts\2026-11-13 17-58-54 - Full\pop.bin
Copies with the same issue time get a numbered suffix. Existing receipt folders
are renamed once on upgrade; receipt hashes are unchanged and stored references
are updated. Old saved receipt paths continue to resolve through a private map.
The game package-family folders remain stable so editions cannot be confused.
