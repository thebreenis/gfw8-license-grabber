# Adera receipt encoding failure: 2026-11-12

Adera 2.5.2.34894 failed native Xbox sign-in with a newly acquired, signed and unexpired `pop.bin`. The game reached `https://auth.xboxlive.com/XSts/xsts.svc/IWSTrust13`; HTTP 200 contained a SOAP Sender fault, header `X-Err: 0x8015DB00`, and reason text "The creator of this fault did not specify a Reason."

The file was 1,291 bytes: a three-byte UTF-8 BOM followed by 1,288 bytes of XML. Its Microsoft signature and Adera edition validated. Hash-guarded observation of the installed SDK showed 1,291 UTF-16 receipt characters entering authentication. The first code units were 239,187,191,13,10,60: the BOM had become the literal characters U+00EF,U+00BB,U+00BF before the original CRLF and XML. This differs from correctly decoding the UTF-8 preamble.

An encoding-only control removed those three leading bytes from the game receipt file. Every following byte was identical, and Microsoft signature, edition and timestamp checks still passed. The same game/SDK and authentication endpoint then received 1,288 characters, issued an Xbox token without a fault, returned HTTP 200 for profile requests, and displayed the signed-in profile. A subsequent ordinary launch with no instrumentation also displayed the signed-in profile. This identifies the BOM handling as the cause in this tested case; it does not assign a universal meaning to `0x8015DB00`.

GUI 1.5.1 and CLI 1.1.1 omit a leading UTF-8 BOM on fresh receipt downloads and imported saved copies. They preserve XML bytes after the preamble. Imported normalized copies are signature-checked again and their proof records use the new file hash. Original imported source files and existing saved receipts are not bulk rewritten. No game binaries, authentication endpoints or license claims were modified.

Seven encoding/import checks passed, including Microsoft-signature preservation with the original receipt, unchanged XML whitespace, BOM-free input, embedded/partial marker bytes, and saved proof hashes. A fresh live Adera receipt downloaded through the corrected code was BOM-free and signature-verified. Existing 23 CLI checks, bulk folder checks and package checks passed.

The first tracing run crashed after observer detachment, after the failed authentication had been captured. The crash event was retained; later runs were closed normally before observer exit. The game-data baseline (158 files) and changed/new files were retained privately. Startup/sign-in changed SDK caches, settings, sentient/configuration state and browser cache, and created a crash dump; no baseline file was missing afterward. No gameplay was entered. This is not an assertion that all app data stayed unchanged. No raw receipt, bearer token or profile data is included in this report.
